## User story

As a quality owner, I want one portable, hash-pinned registry for the supplied
15-case corpus so that tests can resolve the same 45 immutable artifacts and 30
physical pages without machine-specific paths or ambiguous custody.

## Business value

Creates the finite identity and custody layer required by later reviewed-claim,
control, and immutable-run stories.

## In scope

- Exactly 15 case records, 30 physical-page records, and 45 PDF/Markdown/JSON
  artifact records.
- Portable corpus-relative paths, immutable hashes and sizes, case categories,
  page maps, source format, and declared layout/complex-element metadata.
- Explicit public/redistributable custody for every case, referencing the
  approved all-corpus decision.
- Validation and negative controls for identity, path, hash, page, role, and
  custody errors.

## Out of scope

- Claim annotations, expert review masks, or claim scoring.
- Target, positive, non-target, negative, or ambiguous control mapping.
- Parser execution, output comparison, or production behavior changes.
- Mutating or relocating source/expert artifacts.

## Technical approach

Add a versioned portable registry beside the Phase 0 benchmark evidence. Reuse
the P00-US01 manifest primitives where compatible, but keep an explicit
`corpus_root` input outside the stored records so the registry contains no
absolute machine path. Resolve and hash artifacts only during validation.

## Acceptance criteria

1. The registry contains exactly 15 unique case IDs, 30 physical pages, and 45
   uniquely owned artifact-role records: one PDF, one expert Markdown, and one
   expert JSON per case.
2. Every artifact path is normalized and corpus-relative; validation rejects
   absolute paths, traversal, missing files, role duplication, and case/path
   collisions.
3. Every recorded size and SHA-256 matches the immutable artifact bytes.
4. Every case records its category, PDF source format, physical page map, any
   known printed-page label, layout characteristics, and complex-element
   categories; aggregate page counts match the PDF records.
5. All 15 cases reference the approved public/redistributable, no-exceptions
   custody decision; missing or unknown custody fails closed.
6. Validation works from an explicitly supplied corpus root and stores no
   machine-specific workspace path.

## API and schema compatibility

No public API or production-schema impact. The registry is a versioned
benchmark/test artifact.

## Risks

- Accidentally copying machine-specific absolute paths from the frozen analysis
  manifest.
- Treating printed page labels as physical indices.
- Future artifact replacement without an explicit registry version/hash change.

## Rollback

Remove the portable registry and validator from active tests while retaining
the immutable supplied artifacts, the frozen analysis manifest, and the
approved custody evidence.
