## User story

As a delivery owner, I want a reproducible current-system baseline, so that every
future story proves its quality and resource impact against the same reference.

## Business value

Replaces the stale planning snapshots (3.365 seconds and 76 tests) and the
immediate pre-story one-off catastrophe observation (8.502 seconds) with an
auditable distribution, compatibility evidence, and explicit environment
identity.

## Problem statement

Current measurements are incomplete, model integrations are partly skipped, and
the frontend was not run on its supported Node version.

## In scope

- Reference commands/environment and repeated parser runs.
- JSON/Markdown/text hashes and source-grounded quality metrics.
- p50/p95 time, peak RSS, output size, pass/skip counts.
- API/schema and supported frontend serializer baseline.

## Out of scope

- Fixing any defect.
- Changing production dependencies or default settings.
- Live hosted/model calls.

## Technical approach

Add a deterministic benchmark runner/report in the test tooling, run it on the
approved reference environment, and store raw evidence separately from summaries.

## Acceptance criteria

1. At least five reference runs record p50/p95 duration and peak RSS.
2. Output hashes, versions, settings, hardware, and commands are recorded.
3. All catastrophe quality failures from the assessment appear in the baseline.
4. API/schema contracts and frontend serializers run on supported runtimes.
5. Skips are enumerated with owners/reasons; no failure is silently normalized.
6. Rerunning the report produces the same quality counts and stable fixture hashes.

## Dedicated tests

- Unit tests: metric aggregation and hash stability.
- Integration tests: [tests/stories/phase_00/test_p00_us03_baseline_report.py](../../../tests/stories/phase_00/test_p00_us03_baseline_report.py)
- Negative tests: missing environment/version/output and unstable fixture hash.
- Contract tests: `tests/contract/` plus frontend normalization contract.
- Fixture-based tests: catastrophe benchmark and small synthetic controls.

## Regression impact

Run all Phase 00 tests, existing backend suite, API contracts, and supported
frontend unit tests.

## Metrics

- Before: 130 pass / 10 skip after P00-US02; one retained catastrophe parse at
  8,502 ms and approximately 1,427.5 MiB. The older 76-test/3,365-ms figures
  are historical planning snapshots.
- Target: reproducible quality counts and p50/p95/RSS from ≥5 runs.
- After: 156 pass / 10 explicit skips; five cold runs with p50/p95 parse time
  8,050.770/11,955.223 ms and p50/p95 peak RSS
  1,426.97/1,428.33 MiB. See `../metrics.md` and
  `../evidence/P00-US03-baseline.*`.

No behavior change; baseline records the existing contract.
