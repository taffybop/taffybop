# P02-US04 — Reconcile native, font, and OCR candidates

Status: Done  
Story points: 5  
Phase: Phase 2 — Text Integrity  
Priority: High  
Dependencies: P02-US03  
Feature flag: `parser.text_reconciliation.enabled`

## User story

As a downstream LLM consumer, I want competing text candidates reconciled by
source evidence and geometry, so that output contains one accurate representation
without hiding uncertainty.

## Business value

Improves correctness and avoids both duplicate native/OCR blocks and ungrounded
semantic repair.

## Problem statement

Current native/layout agreement is not independent evidence, and reconciliation
cannot compare font-derived alternatives with selective OCR at span level.

## In scope

- Evidence independence, overlap, script/language, and confidence rules.
- Selected candidate plus preserved alternatives and reason.
- Unresolved conflict concern.

## Out of scope

- Language-model completion.
- OCR token cleanup/dedup rules addressed separately.

## Technical approach

Score candidates by source independence, mapping safety, geometry, and OCR
confidence; require defined margins; retain conflicts rather than guessing.

## Acceptance criteria

1. Deterministic font evidence wins the catastrophe damaged spans.
2. Independent high-confidence OCR can win when native/font evidence is unsafe.
3. Engines consuming the same bad text layer do not count as independent agreement.
4. Overlapping alternatives do not duplicate canonical text.
5. Low-margin conflicts remain unresolved with all alternatives and concerns.

## Dedicated tests

- Unit tests: evidence ranking and overlap.
- Integration tests: [tests/stories/phase_02/test_p02_us04_text_reconciliation.py](../../../tests/stories/phase_02/test_p02_us04_text_reconciliation.py)
- Negative tests: conflicting plausible strings, partial overlap, mixed scripts.
- Contract tests: selected/alternative provenance and v1 projection.
- Fixture-based tests: font-repair, scanned, mixed-native/OCR PDFs.

## Regression impact

Run Phase 00–02, OCR, Unicode, reading order, serializer, and API contracts.

## Metrics

- Before: target remains corrupt; no alternatives.
- Target: exact target; 0 duplicates; 100% selections have reason/evidence; 0 semantic completions.
- After: `../metrics.md`.

## API and schema compatibility

Flag-on text may improve; additive alternatives/concerns require compatibility tests.

## Risks

- Threshold calibration and language/script bias.
- Correct OCR displaced by overly trusted font evidence.

## Rollback

Disable reconciliation and project original native text while retaining diagnostics.
