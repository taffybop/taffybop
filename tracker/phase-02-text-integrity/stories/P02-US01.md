# P02-US01 — Detect malformed PDF font mappings

Status: Done  
Story points: 5  
Phase: Phase 2 — Text Integrity  
Priority: High  
Dependencies: P01-US02  
Feature flag: `parser.text_integrity.font_audit.enabled`

## User story

As a downstream text consumer, I want suspicious font mappings detected before
native text is trusted, so that invisible encoding damage is not labeled healthy.

## Business value

Finds the root cause of missing Unicode text cheaply and prevents two extractors
sharing one bad text layer from creating false confidence.

## Problem statement

The catastrophe Type0 fonts map many visible non-space glyphs to U+0020, yet page
coverage is high and no concern or fallback is triggered.

## In scope

- Used-font and glyph-run health signals.
- Collapse-to-space/replacement/private-use/advance anomalies.
- Font/run concerns, evidence, and cached per-font results.

## Out of scope

- Repairing text.
- OCR or semantic completion.
- Persisting extracted embedded fonts.

## Technical approach

Inspect font dictionaries, used CIDs, mappings, advances, and embedded-program
availability. Emit reason-coded health findings without changing text.

## Acceptance criteria

1. Both malformed catastrophe font subsets are flagged with reason codes.
2. Healthy Type0/WinAnsi controls are not flagged.
3. Missing-map, non-identity, and no-embedded-font cases are distinguished.
4. Findings include font object, affected bbox/runs, counts, and confidence basis.
5. Audit is cached per font and stays within the approved healthy-PDF overhead.

## Dedicated tests

- Unit tests: [tests/stories/phase_02/test_p02_us01_font_audit.py](../../../tests/stories/phase_02/test_p02_us01_font_audit.py)
- Integration tests: PDF adapter produces IR font concerns.
- Negative tests: healthy unusual fonts and intentionally spaced glyphs.
- Contract tests: additive concern/evidence fields and flag-off parity.
- Fixture-based tests: bad, missing, healthy, and non-identity font PDFs.

## Regression impact

Run Phase 00–02, PDF input/native extraction, contracts, and performance smoke.

## Metrics

- Before: 0 bad-font detections.
- Target: 100% recall and 0 false positives on phase fixtures; healthy p95 overhead ≤10%.
- After: `../metrics.md`.

## API and schema compatibility

Flagged mode adds internal/additive concerns only; existing text remains unchanged.

## Risks

- False positives on legitimate custom encodings.
- Low-level PDF parser complexity and malformed-input security.

## Rollback

Disable the font-audit flag; native extraction continues unchanged.

## Benchmark evidence — LlamaParse-15

- Related gap: `GAP-UNICODE-001`.
- Cases/pages/regions: catastrophe-recap p1 damaged narrative containing
  `Windstorm Éowyn … (€620 million)` and the chart-label font; esg-metrics p1
  notes 3–7 around `y=391–431`; clinical-study p1 names/diacritics are a
  diagnostic non-assumption target.
- Current behavior: visibly bad native mappings can retain high page coverage
  and produce no document warning; the catastrophe run trusts corrupted spacing
  and Unicode, while esg-metrics superscripts become punctuation. The baseline
  does not attribute these failures to a font/run health result.
- Generalized behavior: audit each used font and run for mapping, private-use,
  replacement, collapse-to-space, and advance anomalies; classify font damage
  separately from layout/OCR errors and do not change text in this story.
- Acceptance tests: positive—both reviewed catastrophe subsets receive
  reason-coded findings; non-target—finance-10k pp1–3 healthy native fonts and
  legitimate multilingual text remain unflagged; negative—missing maps,
  non-identity CID mappings, absent programs, ambiguous cmap, and intentional
  spacing are distinguished without unsafe recovery.
- Metrics/performance: 100% recall on curated bad-font targets, 0% false
  positives on approved healthy controls, 100% findings with font/run/bbox
  evidence. Record cache hit rate and p50/p95/RSS against P00-US10; healthy-PDF
  p95 overhead stays at or below 10%.
