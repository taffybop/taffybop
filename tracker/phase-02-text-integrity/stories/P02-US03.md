# P02-US03 — Escalate unresolved spans to selective OCR

Status: Done  
Story points: 5  
Phase: Phase 2 — Text Integrity  
Priority: High  
Dependencies: P02-US02  
Feature flag: `parser.text_integrity.selective_span_ocr.enabled`

## User story

As an operator, I want only unresolved text spans rendered for OCR, so that
damaged text can recover without full-page visual cost.

## Business value

Improves generic font/scanned-text coverage while preserving CPU-only, offline,
cost-aware operation.

## Problem statement

Current routing uses page-global character/coverage thresholds; locally damaged
text on a healthy page never receives visual verification.

## In scope

- Region/span anomaly routing and bounded crop generation.
- DPI/pixel/time limits and OCR evidence capture.
- Native/font/OCR disagreement concerns.

## Out of scope

- Candidate selection/reconciliation.
- Whole-page VLM processing.
- New OCR engine.

## Technical approach

Translate affected glyph-run boxes to padded line crops, reuse shared Tesseract
passes, and attach candidates without replacing source text.

## Acceptance criteria

1. An unresolved damaged span produces only a bounded line/region render.
2. Healthy spans on the same page are not rendered.
3. Crop bbox, transform, DPI, pixels, OCR pass, confidence, and cost are recorded.
4. Pixel/time limits fail to a concern without losing native evidence.
5. Direct image and PDF-render OCR use the same token/evidence contract.

## Dedicated tests

- Unit tests: crop/transform/limit routing.
- Integration tests: [tests/stories/phase_02/test_p02_us03_selective_span_ocr.py](../../../tests/stories/phase_02/test_p02_us03_selective_span_ocr.py)
- Negative tests: off-page bbox, huge crop, timeout, unavailable OCR.
- Contract tests: OCR evidence/provenance and flag-off behavior.
- Fixture-based tests: unresolved-font and healthy-neighbor PDFs.

## Regression impact

Run Phase 00–02, shared OCR, image/PDF parity, timeout, and performance tests.

## Metrics

- Before: no OCR for the damaged line.
- Target: unresolved span OCR coverage 100%; healthy-page rendered area below approved threshold.
- After: `../metrics.md`.

## API and schema compatibility

No default change. Additive evidence/concerns only until reconciliation.

## Risks

- Incorrect PDF-to-render coordinate transforms.
- Crop overhead on documents with many small anomalies.

## Rollback

Disable selective span OCR; audit/recovery evidence remains.

## Benchmark evidence — LlamaParse-15

- Related gaps: `GAP-UNICODE-001`, `GAP-TEXT-001`, `GAP-OCR-001`.
- Cases/pages/regions: unresolved catastrophe-recap p1 glyph-run boxes;
  esg-metrics p1 note-marker spans around `y=391–431`; clinical-study p1
  diacritic/word-boundary spans and p4 minus/decimal span; component-datasheet p2
  small pin/note labels as an OCR-size stressor.
- Current behavior: locally corrupt text on otherwise healthy pages can miss
  page-global OCR thresholds, while broad visual passes elsewhere produce noisy
  chart/diagram text. Crop transform, cost, and failure evidence are not exposed
  as one span-level contract.
- Generalized behavior: render only audited unresolved spans with bounded
  padding/DPI/pixels/time, attach OCR candidates and word boxes without
  selection, and preserve the native/font alternatives and coordinate transform.
- Acceptance tests: positive—an unresolved reviewed span yields one bounded,
  attributable OCR candidate; non-target—healthy neighboring text and
  finance-10k pp1–3 are not rendered; negative—off-page or oversized boxes,
  unavailable OCR, timeout, low-evidence micro-labels, and transform mismatch
  emit concerns without replacing native text.
- Metrics/performance: 100% routed unresolved spans, 0 healthy-neighbor renders,
  and 100% candidates with crop/DPI/pixel/time/method evidence. Record rendered
  area plus OCR p50/p95/RSS against P00-US10 and keep total healthy-PDF p95
  overhead within 10%.
