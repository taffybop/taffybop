## User story

As a document consumer, I want running headers, footers, navigation, and printed
page labels separated from body content, so that page identity and reading order
remain correct for excerpts.

## Business value

Prevents headers from becoming headings, footers from contaminating body bboxes,
and physical page index from being confused with the printed source page.

## Problem statement

The 15-case corpus contains non-contiguous printed pages. The current output
stores physical indices as page labels, inconsistently types repeated headers,
and sometimes orders navigation/title fragments incorrectly.

## In scope

- Physical index, embedded PDF label, source-visible detected printed label,
  safe legacy/physical fallback, and display text as independent fields.
- Header/footer/navigation classification from bounded source, ownership,
  geometry, layout-role, and exact-repetition evidence.
- One bounded native-source extracted-contribution path for a running header
  fused into a visual/body predecessor, with byte-exact inverse reconstruction.
- Strict additive public, IR, canonical, API, and frontend contracts.
- Stable canonical Body versus Full policy, physical-only navigation,
  bidi-isolated printed-label display, and page-scoped copy/download parity.
- Default-off, page/document fail-closed rollback, idempotence, terminal
  source-alignment strip/replay, resource/deadline limits, and retained metrics.

## Out of scope

- Renumbering source documents.
- Guessing absent pages.
- Removing running content from evidence.

## Technical approach

Detect repeated boundary regions and bare printed labels using geometry,
typography, and cross-page repetition. Preserve every region in IR while
projecting it according to an explicit body/full policy.
