# P03-US05 — Preserve source-visible redline and text-run semantics

Status: Done  
Story points: 5  
Phase: Phase 3 — Layout  
Priority: High  
Dependencies: P01-US02, P03-US04  
Feature flag: `parser.layout.text_run_semantics.enabled`

## User story

As a legal-document consumer, I want deletions, insertions, underlines, colors,
and placeholders tied to exact text runs, so that active and superseded contract
language are not flattened into the same plain text.

## Business value

Prevents legally material meaning changes while providing a reusable run-level
model for styled PDFs and later Office tracked-change adapters.

## Problem statement

On `purchase-agreement` page 1, both the expert and the P03-US04 predecessor
lose parts of the strike/underline semantics. The historical baseline also
moved the redline banner after the body; P03-US04 repaired that order, and
US05 must preserve it while adding run semantics.

## In scope

- Run-level font/color/style evidence.
- Geometry association between text runs and strike/underline rules.
- Orthogonal deletion/unknown state, decorations, style, and placeholder
  evidence. Inserted/replacement states require explicit native
  tracked-change metadata and are not inferred by the PDF adapter.
- Redline-preserving and active-text presentation policies.

## Out of scope

- Inferring legal intent without source evidence.
- Accepting/rejecting tracked changes.
- General OCR handwriting or signature interpretation.

## Technical approach

Associate vector rules and style spans to text geometry with bounded tolerances,
retain raw runs in the shared IR, and expose a conservative semantic state.
Ambiguous overlaps remain styled evidence with a concern rather than a guessed
legal change. The accepted contract is
[P03-text-run-semantics-policy.md](../decisions/P03-text-run-semantics-policy.md).

## Acceptance criteria

1. All six reviewed logical deleted spans are present with seven exact unique
   change-group/rule associations and nine exact run/rule links; the 3/3 known
   expert omissions (`Draft of 6/1/20`, `June`, `23`) are repaired.
2. `EXECUTION VERSION` and exactly seven blue underscores retain 2/2 runs and
   4/4 underline-rule associations; the underscore run is a placeholder with
   unknown state, and neither blue run is inferred inserted or deleted.
3. Typed IR and additive JSON retain an allowlisted scalar/table-cell/nested
   target path, exact target-slice offsets, source text, bbox,
   font/size/bold/italic/color, orthogonal state/decorations/placeholder, raw
   rule IDs/bboxes, method, derivation, and deterministic order for every
   scored run.
4. Redline Markdown preserves deletion/underline safely and also serializes
   non-overlapping source-supported bold/italic spans (`**`, `*`, or `***`);
   heading-level emphasis is not redundantly wrapped. The complete
   source-visible scalar remains authoritative; active text removes only
   proven deletions and lists every omitted run ID.
5. False deletion is zero for `EXECUTION VERSION`, `Background`, `Exhibit A`,
   the mandatory postal/finance controls, and frozen table/decorative/
   ambiguous/boundary synthetics.
6. The exact seven-entry source sequence, purchase P03-US04 3/3 pairs, and full
   P03-US04 41/41 order remain correct.
7. Default-off API/Markdown/IR/canonical behavior and source-extractor call
   count are the exact P03-US04 predecessor.

## API and schema compatibility

Public ParseResult and strict canonical-presentation schemas stay at 1.0.
Typed IR records and public item fields are additive behind one default-off
flag. Canonical Markdown uses flagged redline Markdown while canonical text and
the item value retain complete source-visible text. Active text is explicit,
derived, and never the default.

## Risks

- Table/decorative rules mistaken for strike or underline.
- Consumers treating inferred active text as authoritative.
- Geometry thresholds varying with rotation or font metrics.

## Rollback

Disable `parser.layout.text_run_semantics.enabled` for exact P03-US04
predecessor behavior, including no US05 extraction, fields, records, or
diagnostics.

## 2026-08-13 functional-fidelity correction

- A heading is demoted to ordinary redline text only when one source-mapped
  vector run covers the complete scalar, is explicitly marked deleted, and
  source-page geometry proves a compact top-right revision banner. Mid-page,
  broad, or left-aligned deleted headings retain their heading envelope. This
  makes `Draft of 6/1/20` source-visible without fabricating an H1.
- A same-size, fully underlined, unchanged heading below exactly one eligible
  H1 is projected one level beneath it; competing H1 evidence refuses the
  refinement. `Background` is therefore H2 beneath `ASSET PURCHASE AGREEMENT`.
- Purchase defined-term punctuation now accepts one to three exact paired
  source smart-quote pairs only when every quoted interior is byte-identical;
  unmatched, mixed, changed-interior, and ambiguous pairs reject. The already
  reviewed five-pair opening remains under the same exact-pair constraint.
