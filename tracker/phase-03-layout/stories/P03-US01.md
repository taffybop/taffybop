# P03-US01 — Preserve external table captions

Status: Done  
Story points: 3  
Phase: Phase 3 — Layout  
Priority: High  
Dependencies: P01-US02  
Feature flag: `parser.layout.table_captions.enabled`

## User story

As a document reader, I want table captions emitted as distinct linked elements,
so that titles are neither lost nor forced into table cells.

## Business value

Restores Exhibit 7 with negligible compute and generalizes to table titles,
footnotes, and audit citations.

## Problem statement

Docling returns the exact caption, but `_docling_table_item()` ignores it and the
normalizer returns after the table.

## In scope

- Table-caption references and external-caption geometry.
- Distinct caption element, `caption_of`, bbox, source, confidence, order anchor.
- Multiple/ambiguous caption concerns.

## Out of scope

- Table cell changes.
- Visual/chart captions.
- Synthesizing a missing caption.

## Technical approach

Project retained IR caption edges into distinct elements immediately before their
tables when graph and geometry agree.

## Acceptance criteria

1. Exhibit 7 caption appears exactly once with its source bbox.
2. The table links to it using `caption_of`.
3. Caption is not inserted into table rows/cells.
4. Ambiguous/multiple references remain separate with concerns.
5. Flag-off JSON and Markdown match baseline.

## Dedicated tests

- Unit tests: caption relationship projection.
- Integration tests: [tests/stories/phase_03/test_p03_us01_table_captions.py](../../../tests/stories/phase_03/test_p03_us01_table_captions.py)
- Negative tests: internal caption, shared caption, dangling reference.
- Contract tests: additive relationship and canonical Markdown.
- Fixture-based tests: catastrophe and synthetic table-caption graphs.

## Regression impact

Run Phase 00–03, table normalization, reading order, serializers, and contracts.

## Metrics

- Before: Exhibit 7 recall 0/1.
- Target: 1/1; duplicate rate 0; bbox/relationship coverage 100%.
- After: `../metrics.md`.

## API and schema compatibility

Adds a caption item/relationship in flag-on output; v1 compatibility requires
fixture-reviewed ordering.

## Risks

- Duplicate caption if a top-level body node is also present.

## Rollback

Disable table captions; legacy table output remains.

- Acceptance/metrics/performance: raise reviewed external-caption recall from
  0/3 to 3/3 with 0 duplicates, 100% `caption_of`/bbox coverage, and no cell

- Flag/rollback: `parser.layout.table_captions.enabled`; disabling it restores

## 2026-08-14 Clinical physical-page-2 Table 1 correction

The current release path again projects the physical-page-2 Table 1 caption
exactly once and immediately before its owner. The reusable correction does
not require an owner to be promoted to `table`: a unique raw table declaration
may bind to an unresolved `table_candidate` only after the public P04 gate,
sidecar, source identity, grid shape/content, page, geometry, and bounded sparse
topology replay exactly. Ambiguous, weak, conflicting, or malformed evidence
fails closed and does not synthesize a caption or change table cells.

The real-page integration passed **1/1 in 29.74 seconds**. The owner remains an
unresolved `table_candidate` with **32 rows, 6 columns, 166 cells**, and exact
gate coverage **0.864583**. The isolated current-code Clearleaf DOM contains
the caption once before the owner, followed in order by the three notes and
the DOI control, each once. The focused backend gate passed **185** tests; the
frontend source-note gate passed **7** tests and `tsc --noEmit` passed.

This is an append-only correction to the already owned P03-US01 capability,
not a new benchmark gap, story, or defect. The fuller ownership, exactly-once,
and non-release evidence qualification is recorded in the
[P03-US03 correction](P03-US03.md#2026-08-14-clinical-physical-page-2-table-1-correction).
