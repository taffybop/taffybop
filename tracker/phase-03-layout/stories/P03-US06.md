# P03-US06 — Extract form controls and key-value relationships

Status: Done  
Story points: 5  
Phase: Phase 3 — Layout  
Priority: High  
Dependencies: P01-US02, P03-US04  
Feature flag: `parser.layout.forms.enabled`  
Started: 2026-07-31

## User story

As an automation consumer, I want form labels, empty/value regions, and control
states represented explicitly, so that a blank certificate or aligned
datasheet block is not reduced to unordered text or a malformed table.

## Business value

Enables safe form and key-value processing across native PDFs, scanned forms,
images, and future format adapters without inventing values.

## Problem statement

The ACORD page loses label/value/control relationships and has a malformed
coverage grid. Datasheet key/value pairs become alternating unrelated text
items or an ambiguous table.

## In scope

- Form, field/group, label, value region, and checkbox/radio control records.
- Empty, checked, unchecked, ambiguous, and not-applicable states.
- Spatial key-value grouping for aligned, borderless regions.
- Relationship-aware Markdown/JSON fallback without fabricated values.

## Out of scope

- Filling or signing forms.
- Handwriting/signature identity.
- Domain-specific insurance rules.

## Technical approach

Use shared layout geometry, rules, and OCR/native evidence to form typed
label/value/control candidates. Keep empty fields explicit when structure is
source-visible; retain an unresolved group when boundaries or state are
ambiguous.

## Acceptance criteria

1. ACORD producer/contact/insurer/certificate regions expose correct label,
   empty value, and group relationships.
2. All visible insurance checkboxes are represented as unchecked or ambiguous,
   never as missing active choices.
3. Datasheet GPIO/pin and operating-condition pairs remain ordered pairs with
   symbols and units intact.
4. Form groups do not become one false canonical table, and true embedded
   coverage grids remain available to Phase 04.
5. Every field/control has bbox, source, confidence dimensions, and concerns;
   no absent value is fabricated.
6. Flag-off API and Markdown remain unchanged.
7. A resolved static `parties-and-insurers` group may replace predecessor
   contributors only when its complete source graph is closed: the six base
   fields, paired insurer-name/NAIC fields, all native labels, vector-backed
   contained value regions, blank states, visual row order, and exact
   contributor custody must agree. Any incomplete, entered, unresolved,
   concerned, non-target, or geometrically inconsistent group remains inert.
8. For an admitted blank static replacement, raw Markdown and the rendered UI
   present every source label exactly once in visual reading order, retain all
   values as `null` / `value_state=empty` in JSON, render blank value cells,
   and never insert synthetic empty-field prose or imply a user-entered value.
