## Release-first completion comment

Completed the default-off, native-first Office visual-fallback boundary.
Only reason-coded unresolved regions are submitted to an injectable approved
renderer under region, dimension, total-pixel, byte, and deadline limits; the
result reuses the shared visual-service request/normalization contract and an
explicit pixel-to-native transform. Reconciliation is transactional and
deduplicates visual additions without rendering or overwriting valid native
items. Its bounded sidecar and processing summary are closed additive models
advertised in OpenAPI. Renderer absence, timeout, malformed output, or limit refusal preserves
the complete native payload and adds a deterministic concern. Macros, formulas,
external links, and embedded programs are never executed or fetched, and
flag-off returns the native payload unchanged. The focused P07-US08 run passed
6 tests and the cumulative P07-US01–US08 run passed 95 tests, both with 0
failures, 0 skips, and 1 existing Starlette `httpx` deprecation warning.
Deferred whole-document rendering, full semantic-twin, adversarial-renderer,
benchmark, performance/RSS, evidence, and review campaigns were not run and
are not claimed as passed.

## User story

As an Office-document consumer, I want visual fallback applied only to
unsupported native regions and reconciled with source evidence, so that complex
content remains useful without duplicating or replacing native semantics.

## Business value

Extends coverage for layout-dependent or unsupported Office objects while
preserving native-first accuracy, bounded resource use, and deterministic output
when rendering is unavailable.

## Problem statement

DOCX, PPTX, and XLSX native adapters deliberately leave unsupported objects and
some physical geometry unresolved. Whole-document rendering can be expensive,
unsafe, and duplicative; native and visual passes require shared transforms,
evidence reconciliation, and failure behavior.

## In scope

- Eligibility for unsupported/layout-dependent Office regions only.
- Approved sandboxed renderer requests with page/slide/sheet, pixel, time,
  memory, and area limits.
- Shared visual analysis through the P07-US02/P05 contracts.
- Native-first reconciliation, overlap-aware deduplication, transforms,
  relationships, provenance, concerns, and canonical output.
- Deterministic native/unsupported fallback on renderer or analysis failure.

## Out of scope

- Default full-document rendering.
- Executing macros, fields, formulas, external links, or embedded programs.
- Letting visual/model evidence overwrite valid native evidence.
- Adding a new hosted/model path outside Phase 06 controls.

## Technical approach

Select only unresolved native placeholders/regions, render through an approved
bounded interface, map visual evidence back to Office coordinates, reconcile
against native evidence by identity/geometry, and fall back transactionally to
native plus concerns whenever rendering or merge fails.

## Acceptance criteria

1. Valid native text, cells, tables, media, and chart data are never rendered
   for replacement or overwritten by fallback evidence.
2. Only eligible unsupported/layout-dependent regions render, and cumulative
   page/document pixels, area, time, memory, and concurrency remain within
   configured budgets.
3. Every visual item retains renderer/version, crop/page/slide/sheet,
   transform, OCR/analyzer, and native-placeholder provenance.
4. Native and visual evidence reconcile to zero duplicate semantic elements or
   canonical content on approved fixtures.
5. Office-rendered and equivalent PDF/direct-image twins meet P07-US02 semantic
   and geometry tolerances where source capabilities overlap.
6. Missing renderer, timeout, crash, malformed render, transform failure, or
   resource exhaustion returns native evidence plus explicit concerns and never
   fails the entire parse.
7. Flag-off behavior returns native adapter/chart output and placeholders
   unchanged.
8. Completion evidence includes approved DOCX, PPTX, and XLSX native/render
   twins with positive, native-complete non-target, and overwrite/duplicate/
   transform/failure negatives; a missing format twin blocks readiness.

## API and schema compatibility

Flag-on output adds visual evidence/concerns through existing additive IR
contracts. Existing native fields remain authoritative, and flag-off/renderer-
unavailable behavior preserves the native Office result.

## Risks

- Office rendering engines differ in fonts, layout, and platform behavior.
- Renderer dependencies can be large, vulnerable, or license-restricted.
- Incorrect transforms can duplicate or misassociate visual evidence.
- Over-broad eligibility can erase the cost advantage of native parsing.

## Rollback

Disable Office fallback and return native evidence plus unsupported-object
concerns. Stop renderer dispatch without disabling native Office adapters.
