## Release-first acceptance criteria

- Current state: PDF and raster image paths exist, but there is no common
  adapter protocol, capability manifest, registry, or reusable conformance
  layer.
- Production work: add the versioned adapter/capability contract,
  registration/dispatch, coordinate declarations, provenance/fallback fields,
  and compact conformance checks/test doubles.
- Sequence: Phase 07 foundation; required before OOXML/Office adapters.
- Basic validation: existing PDF and image adapters register/dispatch through
  the contract, one conforming test adapter passes, one missing mandatory
  capability fails registration, public output remains compatible, and
  flag-off uses existing dispatch.
- Deferred: exhaustive conformance mutants, performance/resource campaigns,
  large evidence manifests, and independent review.

This section supersedes stricter release validation requirements below.

## Release-first completion comment

Completed with a strict versioned adapter/capability manifest, bounded resource,
signature, origin, evidence, relationship, coordinate-transform, fallback, and
canonical-serialization declarations; a fail-closed registry with deterministic
selection/dispatch; reusable conformance diagnostics; conforming and
nonconforming test adapters; and registered wrappers for the existing PDF and
direct-image loaders. The production dispatch hook is default-off and delegates
to the exact predecessor loader when disabled, so existing public JSON,
Markdown, text, and legacy projections remain compatible. Missing mandatory
capabilities, duplicate MIME/extension ownership, invalid transforms, unstable
registration state, unsafe fallback, absent limits, and signature mismatch are
reason-coded and cannot enable an adapter. The focused and cumulative P07-US01
run passed 15 tests with 0 failures, 0 skips, and 1 existing Starlette `httpx`
deprecation warning. Deferred benchmark, performance, resource, security,
large semantic-twin, evidence, mutant-campaign, and independent-review work was
not run and is not claimed as passed.

## User story

As a parser maintainer, I want every input adapter checked against one reusable
contract, so that new formats cannot bypass evidence, geometry, relationship,
serialization, safety, or fallback guarantees.

## Business value

Creates an enforceable extension boundary, prevents format-specific parser
forks, and makes adapter readiness measurable before a MIME type is enabled.

## Problem statement

PDF and image inputs have working paths but no common capability manifest or
reusable test harness. A future adapter could omit transforms, provenance,
limits, visibility policy, concerns, or canonical compatibility while still
appearing to parse successfully.

## In scope

- Adapter identity/version and MIME/signature capability manifest.
- Source/page/region identity, coordinate units/transforms, evidence methods,
  relationships, concerns, visibility, limits, and fallback declarations.
- Reusable conformance assertions, test fixtures, and conforming/nonconforming
  adapter test doubles.
- Fail-closed adapter registration and capability negotiation.

## Out of scope

- Changing PDF/direct-image semantics.
- Implementing OOXML intake or an Office adapter.
- Requiring every format to expose capabilities absent from its source.
- Production release/canary policy owned by Phase 08.

## Technical approach

Define a versioned adapter protocol on the shared IR and a capability-aware
conformance harness. Validate registration before dispatch, normalize declared
coordinate transforms, and test mandatory invariants separately from optional
format capabilities.

## Benchmark evidence — LlamaParse-15

- Cases/regions: PDF evidence includes `postal-10k` printed pages 2/46/49,
  `settlement-agreement` printed page 24, `uber-earnings` native/derived image
  regions, and page-1 date text outside its reported item box.
- Current behavior: physical index and printed label can diverge; native,
  rendered, OCR, and generated assets need explicit origin; a text claim can
  lack a box that actually covers its source.
- Generalized behavior: every adapter declares index/label semantics, content
  origin, source locator, invertible transform, bbox coverage, fallback, and
  canonical serialization capability.
- Acceptance/tests/metrics/performance: positive conforming PDF/image controls,
  non-target absent native capabilities, and negative missing-origin/label/
  transform/twin evidence; record harness p50/p95 diagnostically and bound peak
  allocation independently.
- Readiness: M5 lacks direct-image, scanned, and Office twins, so conformance
  can be implemented but cross-format enablement remains blocked by
  `GAP-COVERAGE-001`.
- Gaps: `GAP-COVERAGE-001`, `GAP-VISUAL-001`, `GAP-BBOX-001`,
  `GAP-PROVENANCE-001`, `GAP-SERIALIZATION-001`, and `GAP-PAGE-001`.

## Acceptance criteria

1. The contract declares adapter/version, MIME/signature ownership, source
   identity, page/region model, coordinate transforms, evidence methods,
   relationships, visibility, limits, concerns, and fallback policy.
2. Every currently enabled PDF/image adapter passes all mandatory conformance
   assertions without changing its approved output.
3. Test adapters with missing provenance, invalid/non-invertible transforms,
   unstable IDs, undeclared fallback, absent limits, or fabricated capabilities
   fail with actionable reason codes.
4. An unregistered or failing adapter cannot advertise a MIME type or activate
   through configuration.
5. The harness validates canonical JSON/Markdown/text and legacy projection
   without relying only on snapshots.
6. Flag-off dispatch and public API behavior remain unchanged.
7. The contract distinguishes physical index from printed page/slide/sheet
   label and distinguishes native embedded, rendered, OCR, and generated
   content origin; every content bbox covers its cited source after transform.
8. Registration evidence is incomplete and non-enabling when an advertised
   capability lacks its applicable positive, non-target, and negative semantic
   twins.

without comparable Llama input/output is `Unmeasured/Blocked`; no local
benchmark substitutes.

## API and schema compatibility

The manifest, registry, and diagnostics are internal/additive. Existing
endpoints and public v1 output remain unchanged while the flag is disabled.

## Risks

- A PDF-centric contract could constrain native Office semantics.
- Optional capabilities can become loopholes if mandatory invariants are weak.
- An overly rigid harness can discourage legitimate format-specific behavior.

## Rollback

Disable conformance dispatch and return to the existing explicit PDF/image
adapter paths. Keep the harness available as non-blocking diagnostics.
