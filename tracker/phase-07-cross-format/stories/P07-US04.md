## User story

As a Word-document consumer, I want DOCX text, styles, lists, sections, tables,
and media preserved as native evidence, so that editable structure is not lost
or replaced by OCR.

## Business value

Provides fast, grounded Word extraction, reuses the shared table/relationship
IR, and defers rendering cost to a separately governed fallback story.

## Problem statement

The parser has no DOCX adapter. Rendering first would lose run/style/list/table
and relationship provenance, while claiming page geometry from XML alone would
invent layout Word has not supplied.

## In scope

- Visible native text runs, paragraphs, headings/styles, lists, sections,
  headers/footers, tables, and media relationships.
- Logical anchors, source part/XML path, order, styles needed for semantics, and
  visibility/revision policy.
- Native table mapping through the Phase 04 contract.
- Unsupported native-object concerns for later P07-US08 fallback.

## Out of scope

- Rendering or visual fallback, which belongs to P07-US08.
- Native chart extraction, SmartArt semantics, equations, or pixel-perfect
  pagination.
- Legacy `.doc`, macros, field execution, external fetches, or password
  decryption.

## Technical approach

Traverse approved DOCX parts and relationships from P07-US03, emit native XML
evidence in logical document order, resolve styles/lists/sections/tables/media,
and leave physical bboxes unavailable unless source evidence supplies them.

## Acceptance criteria

1. Approved fixtures emit all policy-visible text, styles/headings, lists,
   sections, headers/footers, table cells, and media exactly once in logical
   order.
2. Every emitted element records `native_xml`, package part/XML locator,
   relationship provenance where applicable, and an explicit logical or
   physical coordinate state.
3. Table grids, explicit merges, headers, repeated text, captions, and source
   notes preserve cell/relationship evidence through the Phase 04 contract.
4. The adapter never invents page numbers or bboxes when DOCX supplies only
   logical structure.
5. Unsupported drawings/objects remain native placeholders with reason-coded
   concerns for P07-US08 and do not trigger rendering in this story.
6. Unsafe/over-budget packages fail through P07-US03, and flag-off restores the
   prior unsupported-format behavior.

## API and schema compatibility

Adds a flagged DOCX MIME/extension path and additive native/XML provenance.
Existing formats remain unchanged; unavailable physical geometry uses the
existing explicit nullable/unavailable contract.

## Risks

- DOCX logical structure does not determine rendered pagination.
- Style/list inheritance and revision visibility can be complex.
- Unsupported objects may be over- or under-classified.
- OOXML reader dependencies require license/security review.

## Rollback

Disable the DOCX adapter and stop advertising DOCX support. Return the existing
unsupported-format response; do not invoke an unapproved renderer.
