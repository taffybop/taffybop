images and PDF-rendered pixels, explicit source identity/origin/page-label

codes for geometry, text, type, relationship, concern, duplication, and

## User story

As a document consumer, I want the same pixels to produce equivalent semantics
whether uploaded directly or rendered from a PDF, so that input packaging does
not change the parse.

## Business value

Eliminates path-specific visual behavior, strengthens confidence in shared
chart/diagram services, and supplies the semantic-twin baseline for Office
fallback.

## Problem statement

Direct images and PDF-rendered regions enter related analysis through different
loading, coordinate, and normalization paths. Their text, types, relationships,
concerns, deduplication, or canonical output can diverge.

## In scope

- Direct-image/PDF-render semantic-twin fixtures.
- Shared visual-service request/evidence contract and coordinate normalization.
- Semantic comparison of text, types, relationships, concerns, provenance, and
  canonical presentation.
- Format-specific geometry tolerances and duplicate checks.

## Out of scope

- Requiring byte-identical source IDs or coordinates.
- Office adapters or OOXML package handling.
- Changing OCR/chart/diagram algorithms beyond adapter-path parity.

## Technical approach

Route twins through the same approved visual services, transform both results
into a common comparison space, and apply the P07-US01 conformance harness with
explicit geometry tolerances.

## Acceptance criteria

1. Approved twins produce identical normalized text, element types,
   relationships, concerns, and canonical presentation.
2. Every compared region declares an invertible source transform whose fixture
   round trip differs by no more than 0.5 pixel.
3. Equivalent OCR/chart/diagram evidence is emitted once, with zero duplicate
   visible text or semantic elements.
4. Differences in source identity and permitted geometry are documented rather
   than hidden by snapshot normalization.
5. Malformed, rotated, multi-frame, and unsupported-image controls produce the
   same bounded concern/failure semantics where capabilities overlap.
6. Flag-off PDF and image output matches the approved baseline.
7. Completion evidence includes direct-image/PDF-render and scanned-wrapper
   positive, non-target, and negative twins for text, table, photograph, chart,
   and diagram semantics; a missing required class blocks the parity claim.

## Dedicated tests

- Unit tests: shared visual requests, coordinate normalization, semantic graph
  comparison, geometry tolerances, and duplicate detection.
- Integration tests:
  [tests/stories/phase_07/test_p07_us02_image_parity.py](../../../tests/stories/phase_07/test_p07_us02_image_parity.py)
- Negative tests: impossible transform, orientation mismatch, duplicate
  evidence, truncated image, unsupported frame, and undeclared difference.
- Contract tests: adapter conformance, evidence/provenance, concerns, canonical
  JSON/Markdown/text, and flag-off parity.
- Fixture-based tests: rotated/EXIF images, visual chart, diagram, malformed
  frame, and image-only PDF controls.
- Cross-format tests: direct raster upload and the same raster embedded in PDF.
- Coverage tests: missing scanned or content-type twin, printed-label mismatch,
  native/render duplicate, hidden-text leak, and generated-as-source origin.
- Performance tests: diagnostic twin-path p50/p95, the paired end-to-end
  LlamaParse latency gate where semantically comparable, and independent peak
  RSS limits.

The sole operative latency benchmark is
[`latency-reference-v1.md`](../../benchmarks/llamaparse-15/latency-reference-v1.md).
Before Definition of Done, each semantically comparable twin needs at least
five interleaved candidate/Llama samples; candidate p50 and nearest-rank p95
must each be no greater than the paired Llama values for that case, with no
dropped failures or corpus-average masking and unchanged required semantic
quality/reliability. A direct-image or scanned path without comparable Llama
input/output is `Unmeasured/Blocked`; its local timing or the PDF twin cannot
substitute. Peak RSS remains independently blocking.

## API and schema compatibility

No endpoint or required-field change. Flag-on behavior aligns equivalent input
paths; source-specific identity and geometry remain explicit.

## Risks

- OCR nondeterminism can make parity tests flaky without pinned engines.
- Tolerances that are too loose can hide transform defects.
- PDF resampling or color conversion can create legitimate pixel differences.

## Rollback

Disable image parity routing and restore the independently approved PDF and
direct-image paths.
