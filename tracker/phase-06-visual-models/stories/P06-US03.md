## Release-first acceptance criteria

- Current state: no hosted visual adapter or hosted-policy dispatch path exists.
- Production work: add mockable transport, deny-by-default policy, minimized
  crop request, explicit vendor/model/region/retention authorization, basic
  request/document budgets and timeouts, typed failures, and secret-safe logs.
- Sequence: after P06-US01; production enablement also depends on P08-US09.
- Basic validation: denied policy sends zero calls, one approved mock call
  produces a valid observation, one timeout/quota/malformed response preserves
  deterministic output, budget exhaustion prevents dispatch, and flag-off is
  inert.
- Deferred: live/billable calls, vendor quality/latency campaigns, exhaustive
  privacy/security/adversarial proof, evidence manifests, and regional

Deny-by-default policy and secret/payload exclusion are core production
behavior and are not deferred.

## User story

As a data-governance owner, I want hosted visual inference blocked unless an
explicit policy and budget allow it, so that document content is not sent to an
external service accidentally.

## Business value

Makes selective hosted capability possible without weakening privacy,
residency, retention, audit, reliability, or cost controls.

## Problem statement

Hosted inference introduces data egress, vendor/model drift, credentials,
retention, regional processing, variable cost, quotas, and network failure. A
feature flag alone is insufficient authorization, and CI must never require a
live or billable call.

## In scope

- A mockable hosted transport implementing the P06-US01 contract.
- Tenant/document data-classification policy, vendor/model/region allowlists,
  retention approval, and explicit deny behavior.
- Crop- and metadata-minimization plus redaction-context records.
- Per-request and per-document timeout, retry, token/output, and cost budgets.
- Secret-safe audit events and typed policy/network/quota/schema failures.

## Out of scope

- Enabling hosted inference by default.
- Selecting a production vendor without privacy, security, legal, and
  procurement approval.
- Cross-region failover, unrestricted retries, or sending full documents when a
  region crop is sufficient.
- Routing or merging hosted observations into final output.

## Technical approach

Place a deny-by-default policy gate before a pluggable hosted transport. Build a
minimal region request from approved evidence, reserve budget before dispatch,
validate the constrained response, account actual usage, and return typed
failures without exposing credentials or document payloads in logs.

## Acceptance criteria

1. No request is sent unless the feature flag, tenant/document data class,
   vendor, model, processing region, retention policy, and remaining budget are
   all explicitly allowed.
2. The request contains only the approved crop and minimum required metadata;
   its redaction/data-minimization decision is recorded without logging source
   content or credentials.
3. Request/document cost, timeout, retry, token/output, and area budgets are
   enforced with zero dispatches after a budget is exhausted.
4. Policy denial, timeout, quota, transport error, malformed schema, and unsafe
   response produce typed failures and preserve deterministic fallback.
5. CI uses mock transport only, performs no DNS/network or billable inference,
   and verifies allow/deny and exact budget accounting.

## Dedicated tests

- Unit tests: policy matrix, data minimization, budget reservation/accounting,
  retry/timeout bounds, secret-safe audit, and response validation.
- Integration tests:
  [tests/stories/phase_06/test_p06_us03_hosted_adapter.py](../../../tests/stories/phase_06/test_p06_us03_hosted_adapter.py)
- Negative tests: disallowed data class/vendor/model/region, missing retention

- Contract tests: transport conformance, configuration defaults, additive
  provenance, and flag-off API/serialization parity.
- Fixture-based tests: mock requests for chart, diagram, sensitive-document

- Performance tests: mocked transport timing is diagnostic and budget
  accounting remains deterministic; no live latency or cost test runs in CI.

The sole operative latency benchmark is
[`latency-reference-v1.md`](../../benchmarks/llamaparse-15/latency-reference-v1.md).
Before Definition of Done, an approved non-CI run must collect at least five
interleaved candidate/Llama samples per applicable case under the pinned
LlamaCloud profile; candidate p50 and nearest-rank p95 must each be no greater
than the paired Llama values for the same case. Failures cannot be dropped,
corpus averages cannot mask a case, and required quality/reliability must remain
unchanged. Non-comparable cases are `Unmeasured/Blocked`; mocked or older local
timings cannot substitute. Timeout, retry, cost, privacy, residency, retention,
and deny-by-default gates remain independently blocking.

## API and schema compatibility

The adapter and policy metadata are internal/default-off. Accepted observations
use the additive P06-US01 contract; no public payload exposes secrets, policy
internals, or provider-specific transport fields.

## Risks

- Data-residency, retention, subprocessor, or acceptable-use terms may prohibit
  hosted processing.
- Redaction can remove evidence needed for a correct observation.
- Vendor/model behavior and pricing can change independently of application
  code.
- Retries can duplicate billing or extend latency if idempotency is unclear.

## Rollback

Disable the hosted-adapter flag, deny all policies, and revoke credentials. No
document requires the hosted path because deterministic fallback remains.
