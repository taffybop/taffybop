This section supersedes stricter release validation requirements below.

## User story

As an API and UI consumer, I want accepted model evidence merged additively and
every other path to return the deterministic result, so that optional inference
cannot make a parse unavailable or overwrite source truth.

## Business value

Completes a reversible optional-model path with one canonical presentation,
stable provenance, and reliable output through policy denials, model failures,
grounding rejection, or merge errors.

## Problem statement

Grounded observations are still separate envelopes. Merging them naively can
overwrite raw evidence, duplicate captions or labels, change reading order,
inflate confidence, or make model availability a prerequisite for success.

## In scope

- Idempotent additive merge of P06-US05-accepted evidence into shared IR.
- Stable relationships, ordering, confidence dimensions, concerns, and complete
  model/source provenance.
- Canonical JSON, Markdown, and text projection without duplicate semantics.
- Deterministic fallback for every skip, denial, adapter error, rejection, merge
  error, or disabled feature.
- Merge/fallback reason and quality/resource accounting.

## Out of scope

- Routing, adapter selection, or grounding policy.
- Letting generated evidence overwrite native/OCR/vector/embedded evidence.
- Semantically repairing rejected observations.
- Making visual models a default or required parser dependency.

## Technical approach

Treat accepted observations as new immutable evidence nodes, link them to cited
regions/elements, and regenerate canonical presentation through P01-US04.
Perform merge transactionally: any validation, relationship, serialization, or
resource failure discards attempted additions and returns the approved
deterministic result with a reason-coded concern.

- Generalized behavior: accepted generated evidence remains origin-labeled and
  appears once; rejected identity/value/direction claims never reach canonical

- Acceptance/tests/metrics/performance: positive one-time merge, non-target

- Gaps: `GAP-VISUAL-001`, `GAP-DIAGRAM-001`,
  `GAP-PROVENANCE-001`, `GAP-DIAGNOSTICS-001`, and
  `GAP-SERIALIZATION-001`.

## Acceptance criteria

1. With merge/routing/adapters disabled, JSON, Markdown, text, IDs, reading
   order, confidence, and concerns exactly match approved Phase 05 fixtures.
2. Every merged observation remains additive, retains complete
   model/adapter/prompt/grounding provenance, and leaves cited raw evidence
   byte-equivalent.
3. Reapplying the same accepted envelope is idempotent and introduces no
   duplicate evidence, caption, label, relationship, or canonical content.
4. Canonical backend/frontend JSON, Markdown, and text expose accepted content
   exactly once and preserve documented legacy fallback behavior.
5. Skip, policy denial, unavailable model, timeout, quota, malformed response,
   budget exhaustion, grounding rejection, and merge/serialization failure
   achieve 100% deterministic fallback success.
6. A partial or failed merge cannot escape; each merge/fallback records a
   stable reason code and area/timing/cost accounting without payloads or
   secrets.
7. Canonical output never relabels generated description/identification as a
   source caption/text item and never presents both an alternate visual
   representation and its accepted semantic claim as duplicate content.
8. Rejected false-caption, visual-identity, ungrounded-value, and
   unsupported-direction envelopes produce byte-equivalent deterministic
   canonical content plus only the documented rejection concern.

## API and schema compatibility

Flag-on output adds only validated model evidence and related concerns through
the additive shared IR contract. Public v1 fields are not removed or
reinterpreted, and flag-off/legacy deterministic projection remains available.

## Risks

- Additive evidence can increase response size and serialization latency.
- Stable-ID or relationship collisions can duplicate presentation.
- Downstream consumers may ignore model provenance or uncertainty.
- A non-transactional implementation could leak partial model state.

## Rollback

Disable merge to ignore all accepted model envelopes and return the deterministic
Phase 05 result. Routing and adapters can then be disabled independently without
schema or data migration.

## Release-first completion comment

Implemented a default-off, document-atomic merge that accepts only P06-US05
grounded envelopes, creates a strict additive owner sidecar, preserves the
Phase 05 source projection byte-for-byte, rejects collisions and resource
breaches, and revalidates both the candidate and canonical presentation before
commit. Shared IR carries the sidecar outside the predecessor/source snapshot;
JSON, Markdown, and canonical text label model origin explicitly and render it
once. Skip, denial, unavailable/failed adapter, timeout-style failure,
malformed response, grounding rejection, partial multi-region failure, merge
failure, and serializer failure fixtures all restore the unchanged Phase 05
result. All Phase 06 tests pass using deterministic doubles only; no live,
billable, download, benchmark, evidence-bundle, performance, or security
campaign was run.
