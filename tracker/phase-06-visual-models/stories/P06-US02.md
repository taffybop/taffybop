# P06-US02 — Add an optional local visual-model adapter

Status: Done — release-first core functionality validated  
Completed: 2026-08-12  
Story points: 5  
Phase: Phase 6 — Optional Visual Models  
Priority: Medium  
Dependencies: P06-US01  
Feature flag: `parser.visual_models.local.enabled`

## Release-first acceptance criteria

- Current state: no grounded local model adapter is implemented.
- Production work: add a lazy adapter interface, explicit configured artifact,
  bounded crop/input/output/time behavior, constrained decoding, typed
  unavailable/error results, and deterministic test double.
- Sequence: after P06-US01; may be developed in parallel with P06-US03.
- Basic validation: flag-off/no-artifact loads nothing, one test-double call
  returns a valid grounded observation, one missing/corrupt/timeout case leaves
  deterministic output unchanged, and rollback disables the adapter.
- Deferred: live model quality campaigns, cold/warm latency, RSS/GPU/hardware
  qualification, exhaustive no-network/adversarial proof, and extensive
  artifact/license evidence. The selected production artifact still needs a
  legally usable source/license before enablement.

This section supersedes stricter release validation requirements below.

## User story

As a privacy-conscious operator, I want an optional bounded local visual-model
adapter, so that eligible regions can receive assistance without network
egress or an always-on model cost.

## Business value

Provides an offline escalation option for ambiguous visual regions while
keeping model artifacts, resource use, licensing, and output provenance
explicit and reversible.

## Problem statement

The parser has no provider-neutral local adapter that implements the grounded
contract. Optional model artifacts may be unavailable, corrupt, unlicensed, or
too expensive for the deployment, and model failure must not degrade the
deterministic result.

## In scope

- A lazy, optional local adapter implementing the P06-US01 contract.
- Region-crop input only, with supplied evidence references and bounded pixels.
- Configured time, concurrency, CPU/RAM/GPU, and output-size limits.
- Model name, version, artifact hash, source, license record, and adapter
  version in evidence.
- A deterministic test double and typed unavailable/timeout/resource failures.

## Out of scope

- Enabling local inference by default.
- Runtime download of unapproved weights.
- Hosted inference, routing policy, or merging observations into document
  output.
- Training, fine-tuning, or trusting free-form prose as structured truth.

## Technical approach

Implement the common adapter interface with lazy loading, an approved artifact
manifest, no-network execution, hard request/resource bounds, constrained
schema decoding, and typed failures that leave the deterministic fallback
untouched.

## Acceptance criteria

1. With the flag off, or with no approved artifact configured, the adapter
   loads no weights, performs no inference or network access, and returns the
   unchanged deterministic result.
2. A successful invocation receives only the requested crop and declared
   evidence references and returns a P06-US01-valid observation with complete
   model, artifact, prompt, and adapter provenance.
3. Missing/corrupt weights, malformed output, timeout, and configured resource
   limit violations fail closed with a typed concern and no partial merge.
4. Artifact hash, source, version, license/usage decision, and model-specific
   quality, memory, storage, and hardware budgets are recorded before the
   adapter can be enabled; latency uses only the canonical paired LlamaParse
   gate below.
5. Offline tests detect and fail any attempted network access; all resource
   limits are configuration-tested at their boundaries.

## Dedicated tests

- Unit tests: lazy loading, artifact validation, bounded input/output, schema
  decoding, resource guards, and typed failures.
- Integration tests:
  [tests/stories/phase_06/test_p06_us02_local_adapter.py](../../../tests/stories/phase_06/test_p06_us02_local_adapter.py)
- Negative tests: absent/corrupt/disallowed weights, timeout, out-of-memory
  signal, oversized crop/output, malformed response, and network attempt.
- Contract tests: adapter conformance, configuration defaults, provenance
  fields, and flag-off API/serialization parity.
- Fixture-based tests: deterministic local model double over chart, diagram,
  photo, and unsupported visual regions.
- Performance tests: record model-specific cold/warm timing for diagnosis,
  apply the paired LlamaParse gate to end-to-end latency, and enforce peak
  RAM/GPU, artifact-size, and concurrency limits independently on the approved
  reference hardware.

The sole operative latency benchmark is
[`latency-reference-v1.md`](../../benchmarks/llamaparse-15/latency-reference-v1.md).
Its initial one-sample values are planning/reference ceilings only. Before
Definition of Done, collect at least five interleaved candidate/Llama samples
per applicable case and require candidate p50 and nearest-rank p95 each to be
no greater than the paired Llama value for that case, without dropped failures
or corpus-average masking and without reduced required quality/reliability.
Non-comparable cases are `Unmeasured/Blocked`; local cold/warm values cannot
substitute.

## Regression impact

Run Phase 00–06 in model-disabled and deterministic-local modes, plus image/PDF

## Metrics

- Before: no constrained local visual-model adapter.
- Target: 0 network calls; 100% successful observations satisfy the grounded
  contract; 100% adapter failures preserve deterministic fallback; resource
  use stays within the approved model-specific budget.
- After: `../metrics.md`.

## API and schema compatibility

The adapter is optional, internal, and default-off. Valid observations use only
the additive P06-US01 contract; flag-off public output remains unchanged.

## Risks

- Model weights or native runtimes may materially increase image size and
  memory/GPU requirements.
- Artifact and model licenses may not permit the intended deployment.
- Hardware-dependent numerical output can reduce reproducibility.
- A local model can still generate plausible but ungrounded content.

## Rollback

Disable the local-adapter flag and remove the optional artifact from deployment;
the deterministic Phase 05 path remains the complete fallback.
