- Current state: no model-observation grounding/validation service exists.
- Production work: resolve submitted evidence IDs and page/region/bbox
  references, validate method/explicit-versus-derived status, reuse P05
  structure/value rules, and return immutable accepted/rejected envelopes.
- Sequence: after P06-US04 and P05-US05; required by P06-US06.
- Basic validation: one grounded observation is accepted, one unknown or
  outside-crop reference is rejected, one structurally invalid chart/diagram

- Deferred: full hallucination/adversarial matrices, statistical calibration,
  corpus-wide grounding rates, performance/resource campaigns, and evidence

This section supersedes stricter release validation requirements below.

## User story

As a document consumer, I want model observations accepted only when they cite
submitted source evidence and satisfy deterministic structure rules, so that a
plausible model response is not mistaken for source truth.

## Business value

Creates an auditable quality gate between optional inference and document output
and reuses deterministic chart/diagram validation instead of trusting model
confidence.

## Problem statement

A correctly routed adapter can still return unknown evidence IDs, claims outside
the submitted crop, contradictory labels, or impossible structure. Adapter
schema validity alone does not prove that an observation is grounded or safe to
merge.

## In scope

- Region/evidence ID, page, bbox, crop, and submitted-input grounding checks.
- Explicit-versus-derived method and confidence validation.
- Phase 05 chart/diagram structural and numeric validator integration.
- Accepted/rejected observation envelopes with reason-coded concerns.
- Validation traces that do not alter deterministic evidence.

## Out of scope

- Region eligibility or adapter selection.
- Repairing invalid model output by semantic inference.
- Merging accepted evidence or changing canonical output.
- General confidence calibration or human-review routing.

## Technical approach

Resolve every observation reference against the exact submitted evidence set,
verify spatial and method consistency, then pass typed chart/diagram structures
through Phase 05 validators. Return an immutable accepted or rejected envelope
with complete validation reasons; never mutate cited evidence.

## Benchmark evidence — LlamaParse-15

- Cases/regions: `uber-earnings` page 1 image with no caption; page 2 New
  Zealand flag and bar/line marks; page 3 gray connectors without arrowheads.
- Current behavior: plausible image prose, the Australia identity, exact
  intermediate values, and directed Mermaid edges can outrun the evidence that
  is actually visible.
- Generalized behavior: validate claim type against crop pixels/vector marks,
  require explicit-versus-derived method and tolerance, and accept direction
  only when a connector supplies directional evidence.
- Acceptance/tests/metrics/performance: positive printed endpoint/node-label
  controls, complete-region non-targets, and the four hard negatives above;
  require stable rejection reasons and record evidence-resolution timing for
  diagnosis.
- Gaps: `GAP-VISUAL-001`, `GAP-CHART-002`, `GAP-DIAGRAM-001`,
  `GAP-BBOX-001`, `GAP-PROVENANCE-001`, and `GAP-DIAGNOSTICS-001`.

## Acceptance criteria

1. Every accepted observation references the submitted region and valid
   evidence IDs on the same page and within the approved crop/relationship
   scope.
2. Unknown, cross-page, out-of-crop, unsupported-type, and overwrite claims are
   rejected with stable reason-coded concerns.
3. Invalid chart/diagram structures, missing value provenance, geometry
   conflicts, and annual-total-below-1H observations are rejected.
4. Accepted observations retain model/adapter/prompt provenance, method,
   confidence dimensions, validation version, and all cited evidence IDs.
5. Repeated validation is deterministic and leaves native, OCR, vector, table,
   chart, diagram, IDs, and reading order unchanged.
6. Flag-off behavior prevents model promotion and leaves public output identical
   to the routed deterministic input.
7. A source-caption claim on the no-caption photograph, the Australia identity
   for the New Zealand flag, an exact unprinted value without mark/axis
   provenance and tolerance, or a directed edge without an arrowhead is
   rejected with a claim-specific reason.
8. Explicit printed chart endpoints and node labels remain accepted source
   evidence and are not duplicated or downgraded when a neighboring model claim
   is rejected.

- Fixture-based tests: grounded labels, valid and invalid chart values, diagram

- Benchmark controls: Uber source-label positives; `postal-10k` complete-table
  non-target; no-caption, NZ/Australia, ungrounded-intermediate-value, and
  no-arrowhead-direction negatives.
- Performance tests: grounding/validator overhead per observation and bounded
  evidence-resolution memory.

The sole operative latency benchmark is
[`latency-reference-v1.md`](../../benchmarks/llamaparse-15/latency-reference-v1.md).
Grounding/validator p50/p95 is diagnostic only. Before Definition of Done,

candidate p50 and nearest-rank p95 must each be no greater than the paired
Llama value for that case, with no dropped failures or corpus-average masking
and with required quality/reliability unchanged. A non-comparable case is
`Unmeasured/Blocked`; no local timing substitutes. The bounded-memory gate
remains independent.

## API and schema compatibility

Accepted/rejected envelopes remain internal/additive in this story. Public v1
JSON, Markdown, and text are unchanged because merging is deferred to P06-US06.

## Risks

- Valid evidence references can still support a semantically incorrect claim.
- Over-strict spatial checks can reject useful observations near crop edges.
- Validator-version drift can change acceptance without model changes.
- Model confidence may be mistaken for grounding confidence.

## Rollback

Disable grounding to prevent any model observation from being accepted for
merge. Routing/adapters may remain testable, but deterministic output is the
only usable result.
