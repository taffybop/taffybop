## User story

As a multimodal consumer, I want visual-model observations tied to source
regions and evidence, so that model assistance remains auditable and cannot
replace source truth.

## Business value

Creates one provider-neutral safety boundary for local and hosted models while
preserving the deterministic, source-grounded behavior delivered by Phase 05.

## Problem statement

Free-form visual descriptions can be plausible but unsupported. The current IR
does not define how a model cites source evidence, distinguishes observation
from inference, reports its identity, or fails without overwriting native,
vector, OCR, chart, or diagram evidence.

## In scope

- Provider-neutral request and response contracts for bounded visual regions.
- Document, page, region, element, and evidence references.
- Observation method, model/adapter identity and version, prompt/schema version,
  confidence dimensions, concerns, and explicit-versus-derived status.
- Validation rules that keep model observations supplemental and immutable.

## Out of scope

- Loading or calling a local model.
- Calling a hosted service.
- Routing, merging, or promoting model observations into structured output.
- Accepting chart values or diagram relationships without source evidence.

## Technical approach

Add a constrained visual-model contract to the shared IR. Validate all
references against the submitted region/evidence set, permit only additive
observations, and represent malformed or ungrounded responses as rejected
evidence with concerns rather than document content.

## Benchmark evidence — LlamaParse-15

- Cases/regions: `uber-earnings` page 1 photograph, page 2 first flag and both
  chart panels, and page 3 upper/lower topology diagrams.
- Current behavior: caption-like generated/OCR prose is not reliably separated
  from source captions; New Zealand is misidentified as Australia; unprinted
  values and directed edges can be serialized without a machine-testable
  evidence method.
- Generalized behavior: contracts distinguish source transcription, generated
  description, visual identification, derived measurement, and relationship
  inference; each claim cites the exact crop/mark/axis/connector evidence.
- Acceptance/tests/metrics/performance: add explicit-label positive controls,
  complete-region non-target controls, and false-caption/identity/value/edge
  negatives; require zero unsupported claims and record contract-validation
  timing diagnostically while bounding allocation independently.
- Gaps: `GAP-VISUAL-001`, `GAP-CHART-002`, `GAP-DIAGRAM-001`,
  `GAP-BBOX-001`, and `GAP-PROVENANCE-001`.

Latency follows the sole operative
[`latency-reference-v1.md`](../../benchmarks/llamaparse-15/latency-reference-v1.md)
gate. Contract-validation p50/p95 is diagnostic only. Before Definition of
Done, each applicable case requires at least five interleaved candidate/Llama
samples; candidate p50 and nearest-rank p95 must each be no greater than the
paired Llama value for that case, with no dropped failures or corpus-average
masking and with required quality/reliability unchanged. A non-comparable case
is `Unmeasured/Blocked`; no local baseline substitutes.

## Acceptance criteria

1. Every accepted observation references an existing region ID and at least one
   existing evidence ID.
2. Unknown IDs, overwrite operations, invalid coordinates, and unsupported
   observation types are rejected without changing deterministic evidence.
3. Each observation records method, explicit-versus-derived status,
   adapter/model/version, prompt/schema version, and separate confidence
   dimensions.
4. Contract validation never promotes a model confidence score into text,
   structure, completeness, or value confidence without an explicit mapping.
5. Flag-off JSON, Markdown, text, IDs, reading order, and parse concerns remain
   identical to the Phase 05 deterministic result.
6. Content origin distinguishes source caption/text from model description,
   visual identification, derived measurement, and inferred relationship; a
   generated claim cannot use a source-transcription origin.
7. Accepted derived values declare cited marks/axes, method, units, tolerance,
   and validation state; accepted directed relations cite directional evidence
   rather than spatial proximity alone.

## API and schema compatibility

The contract is internal/additive and default-off. Public v1 output is unchanged
until a later flagged story explicitly serializes a validated observation.

## Risks

- A contract that is too permissive can legitimize unsupported claims.
- A contract that is too narrow can couple the IR to one model or task.
- Model confidence is not calibrated source confidence.

## Rollback

Disable the contract flag and ignore all visual-model observations; retain the
Phase 05 deterministic IR and fallback.
