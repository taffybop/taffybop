## User story

As a reviewer, I want uncertain claims routed as compact grounded packets, so
that I can audit evidence and return outcomes without reconstructing parser
state.

## Business value

Budgeted review focuses human effort on material uncertainty and creates
feedback without presenting low-confidence claims as facts.

## Problem statement

Low-confidence outputs can fall back, but there is no queue-independent packet,
budget policy, outcome contract, or canonical compatibility behavior for
review escalation.

## In scope

- Review packets with source region, evidence IDs, candidates, concerns,
  method/version, confidence dimensions, and tolerance.
- Accept, reject, correct, and unresolved outcome states.
- Document/region/count/cost budgets and deterministic prioritization.
- Queue-independent routing interface and unavailable-route fallback.
- Additive canonical JSON/Markdown behavior for withheld claims.

## Out of scope

- A review UI or queue vendor.
- Sending real documents to an external reviewer.
- Automatically applying reviewer corrections to source evidence.

## Technical approach

Build packets from the shared IR and calibrated decisions, validate every
reference, rank by approved risk/materiality rules, and enforce hard budgets.
Keep review transport replaceable and fall back conservatively when unavailable.

## Benchmark evidence — LlamaParse-15

- Review candidates: NY page 1–3 table grids; Postal page-1 `FERS`/`ClO`;
  purchase top redline/date/order; settlement `Look-Back`; Uber page-1 caption,
  page-2 flag/charts, and page-3 relationships.
- Current behavior: page-level confidence and broad boxes do not give a reviewer
  the exact source region, origin, explicit/derived status, tolerance, or
  canonical impact needed to decide the claim.
- Generalized behavior: compact packets carry physical index plus printed
  label, exact crop/evidence, content origin, candidate/fallback,
  dimension-specific confidence, concerns, and tolerance/validation method.
- Acceptance/tests/metrics/performance: grounded positive packets, clean/
  below-threshold non-targets, and missing-evidence/budget/route-failure
  negatives; measure packet size and review budgets independently and retain
  construction p50/p95 for diagnosis.
- Gaps: `GAP-VISUAL-001`, `GAP-CHART-002`, `GAP-DIAGRAM-001`,
  `GAP-BBOX-001`, `GAP-PROVENANCE-001`,
  `GAP-DIAGNOSTICS-001`, `GAP-SERIALIZATION-001`, and `GAP-PAGE-001`.

## Acceptance criteria

1. Every packet claim has valid source/evidence references, candidates,
   concerns, method/version, confidence dimensions, and tolerance when derived.
2. Missing or invalid grounding rejects the packet and preserves conservative
   parser fallback.
3. Routing never exceeds configured document, region, item, or cost budgets and
   is deterministic for identical input/configuration.
4. Accept, reject, correct, and unresolved outcomes are recorded once using no
   document content in telemetry.
5. An unavailable or failed review route does not fail parsing or promote the
   withheld claim.
6. Flag-off behavior matches P08-US05/06 fallback and canonical serialization.
7. Every packet distinguishes physical index from printed label, source versus
   generated/derived origin, raw evidence from canonical presentation, and
   includes mark/axis/edge method plus tolerance when applicable.
8. Approved benchmark candidates route within configured priority/count/area/
   cost budgets; verified clean elements and unresolved claims without valid
   grounding do not create packets.

## API and schema compatibility

Review fields are additive. Withheld claims remain represented by existing
fallback/concern behavior; canonical output never treats a pending packet as
accepted source content.

## Risks

- Materiality rules can starve lower-ranked error categories.
- Review correction semantics can be confused with source truth.
- Queue failures can create unresolved backlogs.

## Rollback

Disable `parser.review_escalation.enabled`; discard no source evidence and
return to calibrated accept/fallback behavior.
