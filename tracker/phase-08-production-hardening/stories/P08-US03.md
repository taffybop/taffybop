## User story

As a capacity owner, I want comparable stage timing and resource measurements,
so that slow routes can be located diagnostically and resource-intensive routes
can be budgeted.

## Business value

Stage-level measurements support attribution, sizing, and safe deployment of
optional OCR, chart, model, and format capabilities; they do not replace the
end-to-end paired latency gate.

## Problem statement

Only total parse duration is consistently visible. Native extraction, layout,
OCR, normalization, visual analysis, model calls, reconciliation, and
serialization cannot be compared using one measurement contract.

## In scope

- Counts, failures, and duration for every material parser stage.
- Document-level CPU, peak RSS, optional GPU memory/time, retry, and timeout
  measurements.
- Format/content/route dimensions from bounded enumerations.
- Nested-stage and partial-failure accounting.
- Instrumentation overhead measurements against P00 baselines for diagnostic
  attribution and independent resource review, not as a latency comparator.

## Out of scope

- Quality, fallback, escalation, or cost events.
- Host-wide monitoring or autoscaling policy.
- Promising GPU measurements on deployments without GPU support.

## Technical approach

Wrap shared stage boundaries with the P08-US02 primitives, use monotonic timing,
and define non-overlapping accounting rules for nested stages. Collect resource
measurements only at bounded checkpoints supported by the runtime.

## Benchmark evidence — LlamaParse-15

- Cases: historical current-parser totals for the reviewed cases remain in the
  immutable local-baseline artifacts; they are not LlamaParse latency
  observations or live planning/release thresholds.
- Current behavior: only total duration is available, so dense-table analysis,
  OCR recovery, visual classification, chart/diagram analysis, and
  serialization cost cannot be attributed or compared.
- Generalized behavior: emit reconciled stage traces and CPU/RSS/GPU measures
  for deterministic, render/OCR, table, visual, model, reconciliation, and
  serialization paths on a pinned reference environment.
- Acceptance/tests/metrics/performance: positive complete traces, non-target
  telemetry-disabled parity, and negative missing/duplicate/nested/failed
  stages; retain stage p50/p95 diagnostically, apply independent peak-resource
  budgets, and use only paired LlamaParse evidence for latency.
- Gap: `GAP-PERFORMANCE-001`.

## Acceptance criteria

1. Every material stage in the approved inventory emits count, error, and
   duration signals with documented units.
2. Document scope records CPU and peak RSS; GPU metrics appear only when a
   supported device is active and otherwise report an explicit unavailable
   state.
3. Nested, retried, timed-out, and partially failed stages reconcile to the
   test trace without double counting.
4. PDF, image, DOCX, PPTX, and XLSX fixtures use bounded format/route dimensions
   and no source-derived labels.
5. Disabled resource telemetry makes no resource probes and preserves output.
6. Enabled stage p50/p95 is reported diagnostically; peak-RSS overhead stays
   within its approved P00 resource budget; end-to-end latency passes only the
   canonical paired LlamaParse gate below.
7. The five-case source-reviewed quality/attribution subset emits complete
   stage traces whose
   finalized stage counts/durations reconcile with total processing time under
   the documented nested-stage rule, without content-derived telemetry labels.
8. Separately, all 15 canonical LlamaParse rows are represented as individually
   blocking latency controls; a missing, failed, stale, or incomparable row is
   explicit and cannot be reported as a pass.

historical current-parser totals or local stage timings cannot substitute.

## Risks

- Sampling may miss short-lived memory peaks.
- Nested timings can be misinterpreted as additive.
- Resource probes may vary by platform.

## Rollback

Disable `parser.telemetry.resources.enabled`; retain P08-US02 primitives for
other approved instrumentation.
